# INV-001 · Core invariant — provisional implementation profile

Source baseline: consolidated draft v0.2.0 / IR-001. The original working draft has now been retrieved; see `sources/INV-001.md` and `reconciliation.md` for provenance and resolved/deferred differences.

Each meron has an assigned immutable UUID, unique canonical `noi` path, nonblank display name, one primary classification, semantics (definition and responsibility), lifecycle/release mode, a structural authority-scope reference, object metadata, monotonic revision and timestamps. Rust presents nested identity/classification/semantics/lifecycle sections; PostgreSQL stores normalized columns with JSONB roles and metadata.

Paths consist of lowercase dot-separated segments beginning with a letter, with internal single hyphens and digits permitted. Segments are at most 63 bytes, full paths 240 bytes. Names are 200 bytes; semantics fields 8,000 each; subtype/roles 80 bytes each, at most 32 unique roles; metadata 64 KiB. Rust rejects unknown input fields. Database constraints reinforce shape and uniqueness.

All canonical and historical paths are permanently reserved in `mer.identifiers`; renames preserve UUID references and alias resolution. Retired records remain. The implementation reserves foundation paths against renames. Canonical paths do not imply structural parents.

A proposal is admitted as `proposed`. A later explicit lifecycle operation registers it. `uid` is never supplied by an untrusted proposal; bootstrap root authority references itself. Every other meron references an existing live system scope. Governance alone interprets governance authority.

Reconciliation status: see `reconciliation.md` and `sources/INV-001.md`. This remains an implementation profile; deferred draft features are not implied.

Since 2026-11-02 every meron also has a `spec` object (at most 64 KiB) for checked content. It must pass every admitted invariant that applies to the meron's type and subtype, and must stay empty when none applies. `metadata` remains unchecked notes. See "Meron spec and invariants" in `../architecture.md`.
